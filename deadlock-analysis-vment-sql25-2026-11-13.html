Executive summary

Root cause: the payment and refund transactions acquire write locks in opposite table order. Refund processing updates SalesDemo.dbo.Orders before SalesDemo.dbo.Accounts, while payment processing updates Accounts before Orders. The result is a two-resource X-to-X cycle on the primary keys.

Deadlocks #1–#4, #7 and #10 show the direct cycle: one transaction owns an X key lock on Accounts and waits for Orders, while the other owns an X key lock on Orders and waits for Accounts. Deadlocks #5, #6, #8 and #9 add a second manifestation: payment processing holds an X lock on an account and then takes an S lock while scanning Orders; refund processing holds an IX page lock on Orders and waits for that account key.

  1. Standardize transaction order. Change both procedures to acquire the account row first and then the order row. This directly removes the circular wait in all ten graphs.
  2. Reduce the payment order lookup locks. Review an index on SalesDemo.dbo.Orders keyed by (AccountId, Status) and including Amount. Run the Index Tuning goal before implementing any physical design change; existing indexes are not supplied.
  3. Enable optimized locking after ADR. SalesDemo has ADR OFF and optimized locking OFF on SQL Server 2025. Enabling ADR followed by optimized locking can reduce row/page locks held to transaction end, but it is secondary to correcting lock order and does not solve opposite-order writer cycles by itself.
  4. Consider RCSI for the read component. RCSI is OFF for SalesDemo, and the payment subquery is taking an S lock under READ COMMITTED. Enabling RCSI can remove that reader S-lock contribution, subject to application testing and version-store capacity. It will not prevent writer-versus-writer deadlocks.
  5. Retain safe 1205 retry handling. The SQL Agent batches already catch error 1205, but they immediately retry without a randomized pause. Add a short randomized delay only when the transaction is safe to rerun. This limits impact; it does not remove the deadlock cause.

Replace usp_RefundOrder with consistent Accounts → Orders locking order

USE [SalesDemo];
GO

CREATE OR ALTER PROCEDURE [dbo].[usp_RefundOrder]
    @OrderId int
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @AccountId int,
            @Amount decimal(12,2);

    SELECT
        @AccountId = AccountId,
        @Amount = Amount
    FROM dbo.Orders
    WHERE OrderId = @OrderId;

    BEGIN TRANSACTION;

        UPDATE dbo.Accounts
        SET Balance = Balance + @Amount,
            UpdatedAt = SYSDATETIME()
        WHERE AccountId = @AccountId;

        UPDATE dbo.Orders
        SET Status = 'Refunded',
            UpdatedAt = SYSDATETIME()
        WHERE OrderId = @OrderId;

        INSERT dbo.Payments
            (OrderId, Amount, Kind, CreatedAt)
        VALUES
            (@OrderId, -@Amount, 'Refund', SYSDATETIME());

    COMMIT;
END;
GO

Replace usp_PayOrder with the same Accounts → Orders locking order

USE [SalesDemo];
GO

CREATE OR ALTER PROCEDURE [dbo].[usp_PayOrder]
    @OrderId int
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @AccountId int,
            @Amount decimal(12,2);

    SELECT
        @AccountId = AccountId,
        @Amount = Amount
    FROM dbo.Orders
    WHERE OrderId = @OrderId;

    BEGIN TRANSACTION;

        UPDATE dbo.Accounts
        SET Balance = Balance - @Amount,
            UpdatedAt = SYSDATETIME()
        WHERE AccountId = @AccountId;

        -- Keep the account page's open-order total current.
        UPDATE dbo.Accounts
        SET OpenOrderTotal =
        (
            SELECT SUM(o.Amount)
            FROM dbo.Orders AS o
            WHERE o.AccountId = @AccountId
              AND o.Status IN ('Open', 'Refunded')
        )
        WHERE AccountId = @AccountId;

        INSERT dbo.Payments
            (OrderId, Amount, Kind, CreatedAt)
        VALUES
            (@OrderId, @Amount, 'Payment', SYSDATETIME());

        UPDATE dbo.Orders
        SET Status = 'Paid',
            UpdatedAt = SYSDATETIME()
        WHERE OrderId = @OrderId;

    COMMIT;
END;
GO

Retry the refund SQL Agent step with a randomized delay after error 1205

USE [SalesDemo];
GO

SET NOCOUNT ON;
SET DEADLOCK_PRIORITY LOW;
EXECUTE AS USER = N'svc_refunds';

DECLARE @i int = 0,
        @victims int = 0,
        @OrderId int,
        @stop datetime2 = DATEADD(second, 90, SYSDATETIME());

WHILE @victims < 4 AND SYSDATETIME() < @stop
BEGIN
    SET @OrderId = 49998 + @i % 3;

    BEGIN TRY
        EXEC dbo.usp_RefundOrder @OrderId = @OrderId;
    END TRY
    BEGIN CATCH
        IF XACT_STATE() <> 0
            ROLLBACK;

        IF ERROR_NUMBER() = 1205
        BEGIN
            SET @victims += 1;
            WAITFOR DELAY '00:00:00.250';
        END
        ELSE
            THROW;
    END CATCH;

    SET @i += 1;
END;

REVERT;
PRINT CONCAT(@i, ' calls, ', @victims, ' deadlock victims');
